Why this exists

The goal is draft statistics for your team, Full Sense (FS), in the Thai pro league RPL. The questions you want answered are things like: what does FS first pick, what gets banned against them, when the opponent picks hero X what does FS answer with, and how does side choice (blue or red) change behaviour across a series.

Public sites such as Liquipedia list picks and bans per game but not the interleaved order of the draft, and scraping them felt legally risky. So the source of truth is the broadcast itself: you take a screenshot of the draft bar at the end of the draft, and a second one of the post-game screen, and the tool reads them.

The project started in mid September 2026 as a minimap position tracker. On 24 September you decided to throw that away and restart around the draft. The old tracker only exists in git history now.

Facts the design rests on

  • RPL 2025-26: eight teams, double round robin, best of five. Playoffs best of seven.
  • Global Ban-Pick rule: a team cannot pick a hero it already used earlier in the same series. Game 7 of a Bo7 resets this.
  • The loser of the previous game picks side.
  • The draft is 18 steps: 8 bans and 10 picks, alternating between sides in a fixed pattern that the tool knows for the RPL 2026 broadcast layout.
  • The broadcast swaps hero-to-player mapping during the swap phase, so the final post-swap frame is the one to use for who played what.
  • Flowborn is treated as separate heroes per form (Flowborn Carry, Flowborn Mage), decided 26 September. No combining.

The two programs

1. The extractor (built)

A Python program that runs on your PC. It serves a small web app in your browser. You open it by double-clicking RoV Extractor.cmd in the repo root. That launcher installs dependencies if needed, starts the server with auto-reload and LAN access, and opens the browser.

Inside the app there are four numbered stages for each game:

  1. Pick or create a series (date, teams, best of, patch).
  2. Attach the draft screenshot and the post-game screenshot. They are copied locally and also uploaded to Convex file storage, so they no longer need to live on the PC.
  3. Recognise. The tool proposes all 18 draft actions, player names, K/D/A and the winner. Confident matches are marked, guesses are flagged. You fix anything wrong with dropdowns that show hero art.
  4. Check and save. The checks column validates duplicates, Global Ban-Pick, and missing fields. Save writes the game locally and pushes it to Convex.

There is also a Heroes page (the /heroes route). It is the reference table of all 131 heroes with their ban icon and pick art. You verify each pairing and mark it Checked, by clicking the tick or by double-clicking (double-tapping on the phone) anywhere on the row. Saving the page syncs the hero list and art to Convex.

The app works on your phone over the home WiFi. The launcher prints the LAN address. There is no login, so it is for the home network only.

2. The dashboard (not built)

A web app that reads the data from Convex and shows the statistics. The agreed stack is TanStack Start (React) with Tailwind, living in a web/ folder in this same repository, deployed to Vercel or Cloudflare with the root directory set to web. It talks to Convex directly; Python is not involved.

Nothing exists for it yet except the Convex tables it will read and a static mock-up at docs/mockup/index.html.

Why Python and TypeScript together

Python does the image work because OpenCV and RapidOCR are Python libraries. Convex functions must be written in TypeScript, so the convex/ folder holds the schema and mutations. Python calls those functions by name over HTTP using the Convex Python client. The dashboard will be TypeScript because Convex has first-class React bindings. Each language does the thing it is best at and they meet at the Convex API.

Decisions that need you

These cannot be guessed from the code. Answering them unblocks the dashboard.

  1. Who is the dashboard for? Only you and the FS coaching staff, or public? This decides whether it needs a login and whether the art question matters.
  2. Which statistics first? Suggested order: hero table (picks, bans, wins), first-pick and first-ban, response picks, side split. Tell me if something else is more urgent, for example an opponent scouting view.
  3. Filters. By tournament and stage? By patch? By opponent? By date range? Pick the two or three that you will use every time.
  4. Hosting. Vercel or Cloudflare? Both work with a subdirectory. Cloudflare is cheaper at scale, Vercel is simpler to set up.
  5. Data entry pace. Will you enter all of the current season, or only from now on? This decides whether backfilling from VODs is worth automating.
  6. Phone use of the extractor. Is attaching screenshots from the phone the main path, or a nice-to-have? If main, the upload flow deserves more polish.
